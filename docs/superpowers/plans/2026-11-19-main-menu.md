# Main Menu (Painted Triptych) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the character-selection screen as a full-screen main menu: `starting-regions.png` split into three expanding character panels at exactly `100svh` with no scrolling, one scene at a time on phones, and the controls hint moved into the game.

**Architecture:** The markup in `src/ui/layout.js` becomes three `.realm` panels. Each is a `<div>` holding the scene, the character sprite, a full-size pick `<button data-character>`, and a name label. One `#departure` details panel exists, and `src/ui/selection.js` moves it into the chosen realm. The CSS sizes each panel's third of the painting with container-query units, so the panel can animate its width without distorting the art. A tiny pure helper `nextCharacterId` in `src/data/characters.js` drives the arrow keys, phone arrows and swipe. The in-game key strip is a hidden element that `src/ui/hud.js` shows and fades out.

**Tech Stack:** Vanilla JS ES modules, Vite 7, CSS (container queries, `svh` units), Node `node:test`, Prettier 3.

**Spec:** `docs/superpowers/specs/2026-11-19-main-menu-design.md`. One deviation: the storage-unavailable message gets its own `#storage-note` line directly under the save hint, instead of replacing the save-hint text. `select()` rewrites the save hint on every pick, so a separate line is the only way the message stays visible.

## Global Constraints

  - The selection screen is exactly the viewport height (`100svh`) and never scrolls, at every size from 320×480 up. `document.documentElement.scrollHeight === innerHeight` and `scrollWidth === innerWidth`.

Width changes animate over about 450 ms, and are instant under `prefers-reduced-motion` (the existing global reduced-motion rule already zeroes transitions).
  - Phone means a viewport < 700 px wide: one scene at a time, with left/right arrow buttons at mid-height, horizontal swipe, and three dots that show the position and can be tapped. Touch targets are ≥ 44×44 px.
- Content:

  - Text is ≥ 12 px everywhere. Text over the art sits on a dark gradient scrim.
- Accessibility and behavior:
  - Each pick button is `<button data-character aria-pressed>` labelled "Choose <shortName>". Left/right arrow keys move the selection and focus the newly selected pick button. Begin and the secondary buttons are never nested inside a pick button.

- Modify: `src/ui/selection.js` (arrow-key handler)

**Interfaces:**
- Consumes: `CHARACTERS` (array of `{id, ...}` in selection order: scout, builder, survivor).
- Produces: `nextCharacterId(id: string, step: number) -> string`. It returns the id `step` places after `id` in `CHARACTERS` order, wrapping at both ends. Step +1 is the next character and −1 the previous one. An unknown `id` is treated as index −1, so a step of +1 gives the first character.

- [ ] **Step 3: Add the helper**

In `src/data/characters.js`, directly after the `CHARACTERS` array, add:

```js
/**
 * Finds the character a number of places along from another one, in menu order, wrapping
 * around at both ends. The menu's arrow keys, phone arrows and swipes all use it.
 *
 * @param {string} id - The current character's id, such as `scout`.
 * @param {number} step - How far to move: 1 for the next character, -1 for the previous one.
 * @returns {string} The id of the character `step` places along.
 */
export function nextCharacterId(id, step) {
  const count = CHARACTERS.length;
  const index = CHARACTERS.findIndex((c) => c.id === id);
  return CHARACTERS[(((index + step) % count) + count) % count].id;
}
```

```js
  $('realm-prev').addEventListener('click', () => select(nextCharacterId(session.selected, -1)));
  $('realm-next').addEventListener('click', () => select(nextCharacterId(session.selected, 1)));

  // The dots under the panel jump straight to a character.

    .forEach((dot) => dot.addEventListener('click', () => select(dot.dataset.dot)));

  // A sideways swipe on a touch screen steps to the next or previous character.
  // Mouse drags are ignored so desktop clicks never turn into swipes.
  let swipeStart = null;
  const realms = document.querySelector('.realms');
  realms.addEventListener('pointerdown', (event) => {
    swipeStart = event.pointerType === 'mouse' ? null : { x: event.clientX, y: event.clientY };

  realms.addEventListener('pointerup', (event) => {
    if (!swipeStart) return;

      dy = event.clientY - swipeStart.y;

  });
```

In `src/ui/hud.js`, add near the top (after the imports and any existing constants):

```js
// How long the controls strip stays up when nobody moves, and how long its fade-out takes.
const KEY_STRIP_MS = 8000,
  KEY_STRIP_FADE_MS = 600;
```

Inside `createHud`, next to the existing `toastTimer` variable, add `let keyStripTimer;`. Then add these two functions, each with its comment, before the `return`:

```js
  /**
   * Shows the controls strip at the bottom of the screen, then fades it after 8 seconds.
   * Called each time the game screen opens.
   */
  function showKeyStrip() {
    const strip = $('key-strip');
    clearTimeout(keyStripTimer);
    strip.classList.remove('fading');
    strip.hidden = false;
    keyStripTimer = setTimeout(hideKeyStrip, KEY_STRIP_MS);
  }

  /**
   * Fades the controls strip out and then hides it. Does nothing if it is already hidden or
   * fading, so the game loop can call it on every step without cost.
   */
  function hideKeyStrip() {
    const strip = $('key-strip');
    if (strip.hidden || strip.classList.contains('fading')) return;
    clearTimeout(keyStripTimer);
    strip.classList.add('fading');
    keyStripTimer = setTimeout(() => {
      strip.hidden = true;
      strip.classList.remove('fading');
    }, KEY_STRIP_FADE_MS);
  }
```

Change the return to `return { notify, update, showKeyStrip, hideKeyStrip };`, and update `createHud`'s doc comment `@returns` to list the two new functions.
